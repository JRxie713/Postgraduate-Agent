# Postgraduate-Agent

> 大学生辅助学习 AI 数字人系统
> 陪伴式 · 学科化 · 全流程的 AI 学习助教数字人

## 项目简介

本项目是《软件工程》课程设计实现的前端后端分离 Web 应用，面向大学生群体打造 **AI 学习数字人助教**。系统以拟人化数字人为统一交互入口，覆盖 **课前预习、课中答疑、课后复习、作业辅导、备考冲刺** 全流程，实现 "一对一私教 + 智能导学 + 全程陪伴" 的个性化学习体验。

数字人不仅支持语音 / 文字 / 动作多模态交互，还能感知学习状态（疲劳提醒、专注计时、鼓励安抚），并结合大模型能力提供知识点拆解、拍照搜题、错题本、学习路径规划、成长数据看板等核心能力，帮助大学生高效完成日常学习与备考任务。

项目采用前后端分离架构：
- **前端**：基于 Vue3 + Vite + ESLint 搭建工程化脚手架；
- **后端**：基于 Spring Boot + Shiro + MyBatis 实现，包含权限控制、日志管理、数据库交互、统一响应封装等基础能力。

## 核心特性

- **统一数字人入口**：虚拟学习助教形象可自定义学科风格与语气风格，提供语音 + 文字 + 动作的拟人化对话
- **全流程学习闭环**：预习 → 课中 → 课后 → 作业 → 备考，每个环节都有数字人陪伴
- **不直接给答案的答疑模式**：通过「思路 → 步骤 → 提示 → 总结」引导学生自主思考
- **多学科覆盖**：公共课（高数、英语、思政、计算机）+ 专业课（理工 / 文史 / 经管 / 艺术 / 教育等）
- **数据驱动成长**：学习时长、专注度、知识点掌握度雷达图、周 / 月诊断报告
- **学校管理后台**：课程知识库维护、作业发布批阅、班级学习监控与预警

## 系统架构

系统采用前后端分离架构，前端通过 RESTful API 与后端通信，后端按经典分层架构组织代码：

```
┌─────────────┐        HTTP / RESTful         ┌──────────────────────────────────┐
│   Frontend  │  ───────────────────────────> │             Backend              │
│  Vue3+Vite  │                               │  ┌────────────────────────────┐  │
│             │  <── JSON / 统一 Result ────  │  │  Controller 接口控制器层    │  │
└─────────────┘                               │  ├────────────────────────────┤  │
                                              │  │  Service 业务逻辑层         │  │
                                              │  ├────────────────────────────┤  │
                                              │  │  Mapper 数据访问层 (MyBatis) │  │
                                              │  ├────────────────────────────┤  │
                                              │  │  MySQL / Redis 存储          │  │
                                              │  └────────────────────────────┘  │
                                              └──────────────────────────────────┘
```

各层职责：
- **Controller**：接收请求、参数校验、调用 Service、封装 `Result<T>` 统一响应
- **Service / impl**：业务逻辑编排、事务控制、与 Mapper 交互
- **Mapper**：基于 MyBatis 的数据访问层，配合 `resources/mapper/*.xml` 完成 SQL 映射
- **common/result**：`Result<T>` 统一响应封装，统一 code / message / data 结构
- **common/exception**：全局异常处理，统一错误返回
- **config**：Shiro 权限配置、CORS 跨域配置等基础设施

## 本地启动步骤

### 后端启动

1. 克隆仓库到本地
```bash
git clone https://github.com/JRxie713/Postgraduate-Agent.git
cd Postgraduate-Agent/backend
```

2. 修改 `src/main/resources/application.yml`，配置数据库账号密码，后端默认端口：8080
3. 执行启动命令
```
.\mvnw.cmd spring-boot:run
```

4. 启动成功后访问测试接口：`http://localhost:8080/api/test/hello`


### 前端启动

1. 进入 frontend 文件夹
```
cd ../frontend
```

2. 安装依赖
```
npm install
```

3. 启动开发服务
```
npm run dev
```

> 前端默认运行在 3000 端口，后端默认运行在 8080 端口。

## 接口规范

后端所有接口统一返回 `Result<T>` 结构，定义在 [common/result/Result.java](backend/src/main/java/com/demo/scaffoldbackend/common/result/Result.java)：

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

- `code`：状态码，`200` 表示成功，其它值表示业务错误
- `message`：状态描述信息
- `data`：业务数据载荷，泛型 `T` 按接口语义确定具体类型

例如测试接口 `GET /api/test/hello` 返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "message": "考研AI导学系统后端启动成功！",
    "status": "running"
  }
}
```

## 功能清单

### 1. 数字人学习陪伴（统一入口）
- 专属虚拟学习助教形象：可自定义学科风格、语气风格
- 语音 + 文字 + 动作引导，拟人化对话，支持情绪反馈（鼓励、提醒、解惑）
- 学习状态感知：疲劳提醒、专注计时、学习鼓励

### 2. 课程知识智能导学
- 按专业 / 课程 / 章节自动生成学习路径
- 知识点拆解：重点、难点、考点、易错点
- 数字人讲解：图文 + 语音 + 示例，口语化、易懂、好记

### 3. AI 智能答疑（核心）
- 支持自然语言提问：概念、公式、原理、案例
- 支持拍照搜题 / 上传题目（作业 / 习题 / 试卷）
- **不直接给答案**：提供「思路 → 步骤 → 提示 → 总结」引导式讲解
- 多轮追问：不懂可继续问到会

### 4. 作业与习题辅导
- 作业智能分析：难度评估、考点定位、完成时间预估
- 错题自动收录：按知识点生成个人错题本
- 同类题推荐：举一反三，强化薄弱点
- 作业完成度提醒、截止时间提醒

### 5. 预习与复习规划
- 智能生成：预习清单、复习计划、记忆曲线
- 课堂重点回顾：课件解析、笔记提炼
- 考点抽背、概念默写、公式速记

### 6. 课堂辅助能力
- 课件 / PPT / 教材内容智能解析
- 课堂录音转文字、重点提炼
- 听不懂实时问：暂停、重讲、举例子

### 7. 备考冲刺服务
- 真题解析、模拟卷讲解
- 高频考点串讲、押题训练
- 答题技巧、时间分配、应试心态指导

### 8. 学习数据与成长报告
- 学习时长、专注度、薄弱学科、进步趋势
- 知识点掌握度雷达图
- 每周 / 每月学习诊断与提升建议

### 9. 多学科全覆盖
- 公共课：高数、英语、思政、计算机
- 专业课：理工 / 文史 / 经管 / 艺术 / 教育等适配
- 支持自定义课程导入

### 10. 教师 / 管理后台（学校版）
- 课程知识库维护
- 作业发布、批阅、统计
- 班级学习情况监控、预警
- 自定义数字人教学风格

## 组员协作规范

### 常用 Git 命令

- 提交代码至远程仓库：依次执行 `git add .`、`git commit -m "类型: 描述内容"`、`git push`
    - 提交类型说明：feat 新功能、fix 修复缺陷、docs 文档更新、refactor 代码重构
- 拉取远程仓库最新代码：执行 `git pull`
- 强制同步为远程版本（会覆盖本地修改，请谨慎使用）：执行 `git fetch origin` 后再执行 `git reset --hard origin/main`

### 协作要求
1. 所有代码提交前，须在本地测试确保功能正常运行
2. 业务代码修改应通过 Git 提交至远程仓库
3. `settings.xml` 为本机 Maven 环境配置，禁止提交至远程仓库
4. 项目文档统一存放于 docs 目录
5. 推送代码前先执行 `git pull` 拉取最新版本，避免产生冲突

### 代码规范
- 前端代码需通过 ESLint 校验，提交前执行 `npm run lint`
- 后端遵循阿里巴巴 Java 开发手册风格，类名使用大驼峰、方法名小驼峰
- Controller 层只做参数校验与响应封装，业务逻辑一律下沉到 Service 层
- 统一通过 `Result<T>` 封装返回，禁止直接返回裸对象或 Map
